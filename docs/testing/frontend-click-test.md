# 前端点击测试运行手册

## 适用范围

适用于页面、组件和用户交互改动。每个功能点默认选择 3–7 个测试点，至少覆盖一条主要成功路径；只有在边界或失败行为与本次功能直接相关时才加入。

不用于纯后端、纯文档、性能、安全、无障碍审计或全站回归。

## 前置检查

先找到项目已有的启动方式并复用开发服务。页面地址使用当前项目的安全测试地址，例如 `<页面地址>`，不要在文档或报告中写入真实账号、Cookie 或令牌。

```bash
command -v playwright-cli
playwright-cli install-browser --list
```

如果 CLI 或 bundled Chromium 不可用，且当前任务未授权安装环境依赖，则将对应测试点标为 `阻塞`，不要用源码、静态 HTML 或 `curl` 代替真实浏览器通过。

## 标准执行流程

1. 启动并确认应用服务处于可测试状态。
2. 使用 bundled Chromium 打开已知页面：

   ```bash
   playwright-cli open --browser=chromium "<页面地址>"
   ```

3. 获取当前页面快照，按快照中的有效引用执行用户操作：

   ```bash
   playwright-cli snapshot
   playwright-cli click <元素引用>
   playwright-cli fill <输入引用> "<测试值>"
   ```

4. 页面导航、弹窗、提交或异步状态变化后再次执行 `snapshot`，不要继续使用旧页面引用。
5. 观察并记录用户可见结果；需要时保存截图。失败时再补充当前 URL、控制台、请求或 trace 证据。
6. 测试结束关闭会话：

   ```bash
   playwright-cli close
   ```

多个项目或并行测试使用命名会话，并在所有命令中保持同一个 `-s=<会话名>`。

## 测试点设计

| 优先级 | 应覆盖内容 | 示例结果 |
|---|---|---|
| 必选 | 主要成功路径 | 页面跳转、内容变化、按钮状态更新或保存结果可见 |
| 条件必选 | 直接相关的边界或失败路径 | 校验提示、禁用状态、错误提示或失败后的可恢复状态 |
| 按需 | 主要路径中的前置条件 | 登录态、空状态、必要选择或安全测试数据已准备 |

前置数据优先通过 fixture、接口或安全种子准备；本次要验收的行为必须通过真实页面完成。

## 稳定性与证据

- 优先按 role、label 和 accessible name 定位；关键控件可使用稳定的 `data-testid` 或 `aria-*`。
- 避免 CSS 层级、XPath、`nth-child` 和过深的定位器链。
- 等待可见、可用、文本变化、loading 消失或目标请求完成等目标状态，不默认使用 `sleep`、`waitForTimeout` 或 `networkidle`。
- 失败证据至少包含当前 URL 和可见页面状态；按问题复杂度补充截图、控制台、请求或 trace。
- 证据中不得打印或提交认证状态、凭据、个人信息和真实业务数据。

## 报告模板

测试结束后直接输出简洁 Markdown 报告，只陈述实际执行过的操作：

```markdown
## 前端点击测试报告

- 功能：<本次完成的功能点>
- 环境：<页面地址、服务和关键运行条件>
- 浏览器：Playwright CLI / Chromium（headless 或 headed）
- 结论：通过 / 部分通过 / 失败 / 阻塞

| # | 测试点 | 操作 | 预期 | 实际 | 状态 |
|---|---|---|---|---|---|
| 1 | ... | ... | ... | ... | 通过/失败/阻塞 |

### 问题

- 未发现本次功能范围内的问题；或列出失败现象、复现步骤和必要证据。
```

若 CLI、Chromium、运行环境、账号或测试数据不可用，应在报告中说明具体缺失项并使用 `阻塞`，不能因为拿到静态快照就标记为通过。
